# LAMAK Optimization Studio — Version 5

**Five-year CO₂–EBIT decision support for the Eco Chain Reaction project.** The complete project is a static website deployable on GitHub Pages. All numerical data come from `Eco_Chain_Reaction_Model_Updated.xlsx` and the team's 25 shortlisted proposals; the professor's case rules govern feasibility.


## Independent validation — frozen baseline (17 November 2026)

**PASS within the defined 30-option workbook-backed model.** An independently written 130-binary-variable MILP formulation has reproduced the objective endpoints and all three primary 50/50 strategies; all 516 coefficients were reconciled to the revised workbook. A second test discovered that the **Year-4 EBIT ≥ 0** constraint selects the teammate's four-action plan, whereas **five-year cumulative EBIT ≥ 0** selects a different plan with negative Year-4 EBIT. These are distinct rules and neither is known to be professor-mandated.

See **[`VALIDATION_REPORT.md`](VALIDATION_REPORT.md)** for the independently verified results, stress-test sensitivity, limitations, and reproducible source trace. The deployment now fails if the independent MILP cross-check detects a discrepancy.

## Start here — VS Code on Windows

1. Extract the **contents** of `LAMAK_v5_Exact_Optimizer_GitHub_Actions.zip` into the **root** of your cloned `Bi-Objective-Optimization` repository. Replace the older `index.html`, `app.js`, `styles.css`, `data/` and `tests/` files. Include the normally hidden `.github/workflows/` folder.
2. In the VS Code terminal, run:

   ```powershell
   node --check app.js
   node --test tests/v5.test.cjs
   python -m http.server 8000
   ```

3. Visit `http://localhost:8000` in Chrome or Edge. The default is **Core 30 / exact MILP / 50:50 / unrestricted EBIT**. It loads certified results generated by `scripts/solve_exact_v5.py` from the workbook-backed data.
4. Push the changes to GitHub:

   ```powershell
   git add -A
   git commit -m "LAMAK v5: exact 50-50 MILP and progressive packaging"
   git push origin main
   ```

5. In GitHub **Settings → Pages → Source**, choose **GitHub Actions**. In **Actions**, look for **Test and deploy LAMAK v5**. The workflow recomputes the certified results and publishes the website at `https://gscp-game-lamak.github.io/Bi-Objective-Optimization/` once successfully deployed.

The website itself needs no Python, Node.js, paid hosting, secrets or API keys at runtime.

## Optimization scope and evidence

The **30 core source alternatives** comprise:

- 5 distribution relocations (Rome, Florence, Brescia, Piacenza, Milan);
- 5 energy configurations from Lola's shortlist (one installation globally);
- 12 supplier choices (4 materials × 3 adoption tiers);
- 5 transport actions from Mohammad's shortlist (Verona-based, no relocated-DC mix);
- 3 bottle-redesign tiers, encoded as **55 progressive implementation patterns** rather than independent repeated full-adoption actions.

The model has **170 binary columns**, Year 0 through Year 4, a total **10-token** budget, and at most **3 tokens per year**. DC relocation requires 2 tokens in Year 0 and a €90,000 setup charge; transportation estimates must correspond to the chosen distribution centre. Energy is globally exclusive. Supplier material is assigned a *single* adoption tier unless you explicitly model staged sourcing later; the official text only explicitly mentions progressive packaging.

The source workbook has **516** calculated candidate action rows. The interactive extended browser explorer can screen them, but its stock impacts remain uncertain and its results are not certified globally optimal.

## Normalized objectives — important

Let `R` be cumulative five-year CO₂ avoidance (tonnes) and `E` be cumulative five-year change in EBIT (euros). Independently solve maximum `E` and maximum `R`. Use their attained outcomes to define the payoff table:

\[
S_w = w\frac{R-R_{E\mathrm{max}}}{R_{\mathrm{max}}-R_{E\mathrm{max}}}+
(1-w)\frac{E-E_{R\mathrm{max}}}{E_{\mathrm{max}}-E_{R\mathrm{max}}}.
\]

The fixed source-backed anchors for the unchanged v5 core are:

- Maximum EBIT: **+€1,780,451.61**, with **2,701.00 tonnes** avoided.
- Maximum carbon avoidance: **5,984.25 tonnes**, with **−€16,666,409.48** EBIT.

The default unrestricted, equally weighted exact score optimum is **5,834.30 t**, **−€6,165,539.42** over five years (**76.18% normalized score**). This is *not* a recommendation to incur that loss. The professor has not confirmed this formula as the official grading rule.

The **EBIT guardrail** offers separate, clearly labeled, non-official business scenarios:

| 50/50 constraint | CO₂ avoided over five years | Five-year EBIT | Score |
|---|---:|---:|---:|
| None (pure academic score) | 5,834.30 t | −€6,165,539 | 76.18% |
| Loss no worse than €1m | 4,417.96 t | −€679,863 | 69.48% |
| Five-year EBIT nonnegative | 4,049.03 t | +€553,058 | 67.20% |
| Teammate's four-action benchmark | 3,887.82 t | +€1,116,960 | 66.28% |

All scores use **the same anchors**, even when a financial floor is applied. The displayed optimum is MILP certified at the **chosen 5%-step weight** for the **unchanged 30-alternative workbook core** and the selected guardrail. The plotted points form a **sampled Pareto frontier**. It is not proof that all integer Pareto points have been enumerated.

## Exact MILP — recalculate on your own computer

The precomputed reference is in `data/exact_v5.json` / `data/exact_v5.js`; the reproducible solver is `scripts/solve_exact_v5.py`. For the unchanged bundled workbook extraction:

```powershell
python -m pip install numpy scipy
python scripts/solve_exact_v5.py
node --test tests/v5.test.cjs
```

This solves 83 MILPs using SciPy/HiGHS. Results are marked **exact** only if the MILP solver reports successful optimality. Core-30 interactive weight changes use precomputed, exactly solved portfolios for each discrete slider position. No Python code runs on the static website.

If Excel changes again, **first recalculate and save the workbook in Excel**, replace `source/Eco_Chain_Reaction_Model_Updated.xlsx`, and rerun `build_model_data.py` in an environment that has the `artifact_tool` library. Then rerun `scripts/solve_exact_v5.py`. GitHub Actions intentionally rebuilds the MILP from the committed **extracted data**, not by attempting to recalculate Excel formulas with third-party spreadsheet software.

## Model provenance and limitations

The input extractor only reads **nine sheets**: `Inputs`, `Assumptions`, `Routing`, `Suppliers`, `DC Locations`, `Energy`, `Transport`, `Stock Policies`, `Actions`. It never reads `Dashboard`, `Schedule`, `Audit` or `Sensitivity`. Each candidate's origin is displayed as a worksheet and row reference. The JSON includes the SHA-256 digest of the workbook at extraction time.

- PV estimates use the updated workbook's mean-day self-consumption assumption, which differs from the earlier intraday model.
- Region-to-region routing estimates use proxies/calibrated volumes, not measured transport of all 85 wholesaler flows.
- Supplier freight changes are included in the workbook action estimates, but some supplier–inventory interactions are not modeled.
- Inventory holding costs rely on non-official rates, and their CO₂ and OTIF effects are **not known**. Their toggle is OFF by default.
- Service/OTIF cannot be certified. Do not describe these plans as service-feasible until the class simulation validates them.
- Fixed CapEx limits, five-year EBIT floors and loss tolerances are optional decision preferences, **not stated professor requirements**.
- EBIT differs from cash: initial CapEx is a cash outflow; it is not deducted directly from EBIT. Annual depreciation and implementation setup are included in EBIT under the workbook's accounting convention.
- Live edits or PV sensitivity change the input model: the website automatically falls back to clearly labeled **heuristic** screening. To obtain new certified exact solutions, rerun the Python solver with revised extracted inputs.
